# W9.1 — Peak-giveback exit («flow»): armed trail + never-armed dead-trade (без SL от входа)

**Статус:** normative (к исполнению агентом-исполнителем нового / mild-dip бота).  
**Продукт:** Solana Alpha (`solana-alpha`).  
**Ветка интеграции:** `v2`.  
**Лидер-якорь анализа:** кошелёк `8zkgFGVZrDLieViwqiXFCydSX6WL5hsxmUu55yBdsNsZ` (далее **8zkg**).  
**Выборка:** mild-dip-like сессии 8zkg (pc5m ∈ (−20%, 0], vol5m ≥ $2k, liq ≥ $15k, mcap $15k–$300M, age 0.25–72h) + минутные пути Gecko OHLCV entry→exit.  
**Связанные доки:** [`../copytrader/LEADER_8ZKG_AUDIT.md`](../copytrader/LEADER_8ZKG_AUDIT.md) (исторический audit; **не** копировать его time-cap как норму этой спеки), [`INDEX.md`](./INDEX.md).

---

## 0. Что заказчик хочет одной фразой

Внедрить выход так, чтобы бот **уходил в минус (и в плюс) не по фиксированному % стоп-лосса от цены входа**, а по **flow цены относительно локального пика**: сидит, смотрит откат от running high после входа, и когда откат достаточный — **принимает результат** (в том числе убыток) и полностью выходит. Если цена **никогда не доходит до arm**, лидеры всё равно выходят — см. never-armed §4.2 (patience giveback + max-hold), не infinite hold.

В этой спеке слово **flow** = **price-path / peak-giveback flow**.  
**Не** путать с buy/sell pressure, volume-fade или order-flow лентой — на выборке 8zkg они **не** подтверждены как основной триггер выхода.

---

## 1. Цель для агента-исполнителя

1. Заменить (или изначально не ставить) в целевом боте:
   - hard **time-stop** (типа 6m / 15m),
   - hard **SL % от entry** (типа −5% / −10%),
   - hard **TP на фиксированном % от entry** как единственный take-profit (типа +10% full exit на касании).
2. Поставить **единый** exit-engine: **armed peak-trail / peak-giveback**.
3. Убыток — **нормальный исход** того же правила, если локальный пик был мелкий, а откат от него пробил порог giveback.

**Не цель этой спеки:** менять логику **входа**; трогать `copy-trader-8zkg` / mirror; деплоить на VPS; менять другие стратегии (Live Oscar, paper pt1-*).

---

## 2. Эмпирика 8zkg (обязательный контекст; не выдумывать иное)

Замерено на ~53 mild-сессиях с минутным путём (журнал `copytrader-8zkg` + Gecko 1m):

| Факт | Число |
|------|--------|
| Выход на минуте пика | ~11% |
| Выход в пределах 1.5% от пика («снял хай») | ~8% |
| Выход ≥60s после пика | ~89% |
| Медианный giveback от пика на выходе | **≈ −9.5% … −11%** |
| Среди лоссов: сначала были в плюсе по пути (MFE ≥ +1%), потом выход в минус | **100%** |
| «Чистый нож» от входа без зелёного пика (в этой mild-выборке) | **0%** |
| Кластер hard time-stop ±1m от 5/6/10m | максимум ~13–15% — **не** правило |
| Кластер hard SL от entry (−5/−10/−15) | **нет** устойчивого кластера |

**Вывод:** один механизм — **откат от локального пика**. Плюс/минус от входа — следствие высоты пика, а не отдельный SL-модуль.

---

## 3. Определения (норматив)

| Термин | Смысл |
|--------|--------|
| **`entry_px`** | Цена/mark входа позиции (как уже считает бот; зафиксировать один источник mark). |
| **`peak_px`** | Running maximum mark **с момента входа** (обновляется на каждом тике mark, пока позиция открыта). |
| **`mfe_pct`** | `(peak_px / entry_px - 1) * 100` |
| **`giveback_pct`** | `(mark_px / peak_px - 1) * 100` — всегда ≤ 0, когда `mark ≤ peak`. |
| **`arm_pct`** | Порог MFE, после которого трейл **вооружён**. До arm трейл **не** режет по giveback (иначе шум у входа). |
| **`giveback_trigger_pct`** | Положительное число (например `6`): выход когда `giveback_pct ≤ -giveback_trigger_pct` **и** трейл armed. |
| **Flow-exit** | Полный выход по срабатыванию giveback от `peak_px` после arm. Reason в журнале: `peak_giveback` / `flow_giveback`. |
| **Loss-by-flow** | Flow-exit при котором realized PnL от entry **отрицательный**. Это **успешное** срабатывание правила, не баг. |

---

## 4. Алгоритм выхода (обязательный контракт)

На каждом цикле мониторинга открытой позиции (частота mark — как у бота, желательно ≤ 15–30s; не реже 60s):

```
peak_px = max(peak_px, mark_px)
mfe_pct = (peak_px / entry_px - 1) * 100
giveback_pct = (mark_px / peak_px - 1) * 100

if not armed and mfe_pct >= arm_pct:
    armed = true
    journal: trail_armed { arm_pct, peak_px, mfe_pct }

if armed and giveback_pct <= -giveback_trigger_pct:
    full_exit(reason="peak_giveback")
```

### 4.1 Параметры по умолчанию (старт ближе к 8zkg)

| Env (предложение префикса бота) | Default | Диапазон калибровки | Комментарий |
|--------------------------------|---------|---------------------|-------------|
| `*_EXIT_ARM_PCT` | **8** | 5–12 | Когда трейл включается |
| `*_EXIT_GIVEBACK_PCT` | **6** | 5–12 | Ширина отката от пика (было 10 по медиане 8zkg; live mild-dip калиброван на 6 ≈ floor +1.5% при arm) |
| `*_EXIT_NEVER_ARM_PATIENCE_MS` | **300000** (5m) | 0–off / 3–8m | Unarmed: тот же giveback после patience |
| `*_EXIT_NEVER_ARM_MAX_HOLD_MS` | **2400000** (40m) | 0–off / 20–45m | Unarmed: force exit если arm так и не был |
| `*_EXIT_STOP_LOSS_PCT` | **0** / unset | — | **Выключен** — нет SL от entry |
| `*_EXIT_HARD_TP_PCT` | **0** / unset | — | **Выключен** как единственный TP; опционально позже как cap, не в MVP |

Имена env — подставить префикс целевого бота (`MILD_DIP_`, `DIP_BOT_`, …). Главное: **семантика** arm / giveback / disabled time+SL.

### 4.2 Поведение до arm (v1.1 never-armed — обязательный follow-up)

Пока `mfe_pct < arm_pct`, **armed peak-giveback не режет**. Но лидеры (8zkg mild-dip / 7BNax) **не** сидят вечно на never-arm — см. эмпирику ниже. Поэтому после v1 добавлен **never-armed dead-trade**, **без** SL% от entry:

| Правило | Default | Reason | Эмпирика |
|---------|---------|--------|----------|
| После `never_arm_patience_ms` всё ещё unarmed **и** giveback ≤ −`giveback_pct` от (sub-arm) peak | **5m** | `never_arm_giveback` | 8zkg quick-cut ~30% never-arm (hold med ~5m, exit giveback med ≈ −6%); 7BNax never-arm hold med ~3m, ~83% out by 5m |
| После `never_arm_max_hold_ms` всё ещё unarmed | **40m** | `never_arm_timeout` | 8zkg grind-хвост 15–45m (med never-arm ~18m; 40m ближе к p75+) |

Env (mild-dip): `MILD_DIP_EXIT_NEVER_ARM_PATIENCE_MS=300000`, `MILD_DIP_EXIT_NEVER_ARM_MAX_HOLD_MS=2400000`.  
`0` = выключить соответствующую ветку.

**Запрещено:** трактовать это как SL от `entry_px`. Giveback считается от running peak, как у armed trail; max-hold — только если arm так и не случился.

Always-on giveback без arm **нельзя** (симуляция: ~40% eventual winners вышибаются до +8%). Patience 5m + max-hold 40m сохраняет armed-path.

### 4.3 Loss-by-flow (обязательно понять исполнителю)

Пример:

- `entry = 100`, arm = 8, giveback = 6  
- Цена сходит до `108` → armed, `peak = 108`  
- Откат до `101.52` (−6% от пика) → **exit ≈ +1.5% от входа**  
- Убыток vs entry при этих порогах возможен только при **overshoot** mark/fill ниже линии giveback (быстрый слив между тиками).

Если пик был только `+4%` и arm = 8 — трейл ещё **не** armed; после patience срабатывает тот же giveback −6% от peak 104 → `never_arm_giveback` ≈ −2.2% от входа. Если giveback так и не добило −6%, в конце max-hold — `never_arm_timeout`.

**Не** вводить `STOP_LOSS_FROM_ENTRY`.

### 4.4 Размер выхода

- **Full bag** (100% позиции) на `peak_giveback` / `never_arm_giveback` / `never_arm_timeout`.  
- Partial ladder **не** в scope v1.

---

## 5. Что запрещено

1. **Time-stop на armed-позиции** (если трейл уже armed — только giveback). Never-arm max-hold (§4.2) — исключение только пока `armed=false`.  
2. **Stop-loss % от `entry_px`**.  
3. **Hard TP** «коснулись +10% → market sell» как единственная прибыль.  
4. Выход «на пике» / market-sell при обновлении `peak_px`.  
5. Триггер выхода по **volume fade**, buy/sell ratio, «flow» в смысле order-flow — **без новой эмпирики и отдельной спеки**.  
6. Зеркалирование продажи лидера как единственный exit (можно later как backstop — **не** MVP этой спеки).  
7. Трогать `copy-trader-*`, Live Oscar exit policies, `docs/platform/**`.  
8. SSH/deploy на VPS, если задача не помечена deploy-session.
9. Always-on giveback без arm / patience (вышибает winners до +8%).

## 6. Журнал (контракт событий)

Минимум JSONL (или существующий journal бота) — поля:

**При вооружении:**

```json
{
  "kind": "trail_armed",
  "mint": "...",
  "ts": 0,
  "entryPx": 0,
  "peakPx": 0,
  "armPct": 8,
  "mfePct": 8.1
}
```

**При выходе:**

```json
{
  "kind": "exit",
  "reason": "peak_giveback",
  "mint": "...",
  "ts": 0,
  "entryPx": 0,
  "peakPx": 0,
  "exitPx": 0,
  "mfePct": 0,
  "givebackPct": 0,
  "realizedPct": 0,
  "armed": true,
  "holdSec": 0
}
```

`reason` для этого правила — стабильная строка **`peak_giveback`** (алиас `flow_giveback` допустим, но один канон в коде).

**Метрики после N сделок (для приёмки):**

- доля выходов с `reason=peak_giveback`;
- среди них доля `realizedPct < 0` (loss-by-flow) — должна быть **ненулевая** на живом рынке; если 0 при десятках сделок — скорее баг (слишком широкий giveback / не обновляется peak);
- медианный `givebackPct` на выходе ≈ −(giveback_trigger) ± несколько пунктов;
- **не** должно быть доминирования `time_stop` / `stop_loss` (их быть не должно).

## 7. Тесты (обязательны)

Unit-тесты на чистую функцию (без сети), сценарии:

1. **Arm then giveback win:** entry 100 → peak 115 → mark 108.1 при arm=8/gb=6 → exit, realized > 0.  
2. **Arm floor ~+1.5%:** entry 100 → peak 108 → mark 101.52 → exit, realized ≈ +1.5%, reason `peak_giveback`.  
3. **Overshoot loss:** armed peak 108 → mark 97 → exit, realized < 0 (lag past −6% line).  
4. **No arm, deep dump:** entry 100 → mark 90, peak never ≥ 108 → **no** exit from this rule.  
5. **Peak updates:** 100 → 110 → 120 → giveback считается от 120, не от 110.  
6. **No time exit:** возраст позиции 60m без giveback → правило **молчит**.  
7. **No SL-from-entry:** mark = entry * 0.85 при peak=entry*1.02 и arm=8 → **молчит** (не armed достаточно / giveback от мелкого пика может сработать только после arm — проверить согласованно с формулой).

## 10. Калибровка позже (вне MVP)

После ≥50 live/paper сделок с `reason=peak_giveback`:

1. Снять медиану `givebackPct` и долю loss-by-flow.  
2. Если медианный giveback заметно мягче/жёстче −6% — крутить только `*_EXIT_GIVEBACK_PCT` / `*_EXIT_ARM_PCT`.  
3. Не возвращать time-stop «чтобы оборачиваемость была как раньше», пока заказчик явно не попросит отдельной спекой.

## 11. Краткая памятка «зачем так»

Лидер 8zkg на mild-lane **не** выходит на хае свечи и **не** режет фиксированным SL от входа. Он смотрит, **насколько цена откатила от локального пика**, и закрывает позицию — иногда в плюс, иногда в минус. Этот бот должен делать то же самое по явному правилу arm/giveback.
